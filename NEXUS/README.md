# NEXUS Social — версия 2

Это расширенная рабочая основа социальной сети с оригинальным дизайном. Проект использует HTML/CSS/JS, Node.js/Express, PostgreSQL и Socket.IO.

## Почему раньше появлялся `Failed to fetch`
Нельзя проверять регистрацию простым двойным нажатием на `frontend/index.html`. Форма обращается к API на сервере. Запускай сайт по адресу `http://localhost:3000` после настройки сервера и базы.

## Требования
- Node.js 20+
- PostgreSQL 14+

## Быстрый запуск в Windows
1. Установи Node.js LTS и PostgreSQL.
2. Создай базу данных с именем `nexus`.
3. Скопируй `backend/.env.example` в `backend/.env`.
4. В `.env` укажи реальную строку подключения `DATABASE_URL`, длинный случайный `SESSION_SECRET` и свои значения `NEXUS_OWNER_EMAIL`, `NEXUS_OWNER_USERNAME`, `NEXUS_OWNER_PASSWORD`. Пароль главного администратора должен быть уникальным и содержать минимум 14 символов.
5. Открой терминал в папке `backend` и выполни:
   ```
   npm install
   npm start
   ```
6. Открой `http://localhost:3000`. Схема SQL применяется автоматически при старте.

## Что уже подключено к базе/API
- Регистрация и вход по email/username, выход, серверные сессии, хеширование паролей.
- Уникальный username и ID, профиль, редактирование профиля, приватность, удаление аккаунта.
- Посты, загрузка одного изображения или видео до 30 МБ, лента, видео-лента, поиск по тексту, лайки, комментарии, репосты, избранное, удаление/редактирование своих постов.
- Подписки и поиск пользователей.
- Кланы: создание, вступление/выход, участники.
- Уведомления о подписках, лайках и комментариях.
- Ивенты: просмотр и регистрация участников; создание доступно модератору/администратору.
- Рейтинг пользователей.
- Личные сообщения с Socket.IO и историей в PostgreSQL.
- Жалобы и расширенная базовая админ-панель: список пользователей, роли, блокировки, разблокировки, статистика и журнал действий.
- Защищённая роль `owner` (главный администратор), создаваемая один раз при первом запуске из переменных окружения. Обычная регистрация не позволяет получить эту роль. Главный аккаунт нельзя удалить или понизить через API; назначать/снимать роли администраторов может только владелец.
- Светлая/тёмная тема и адаптивный интерфейс.

## Создание главного администратора

При первом запуске сервер создаст отдельный аккаунт `owner`, если в базе ещё нет владельца. Заполни три переменные `NEXUS_OWNER_*` в `backend/.env` до запуска. Если указанные email/username уже заняты, сервер остановится с понятной ошибкой и не повысит существующий аккаунт автоматически. После создания аккаунта пароль из `.env` не используется для сброса; для смены пароля нужна отдельная безопасная процедура. Не отправляй `.env` никому и не добавляй его в ZIP/репозиторий.

## Честно о незавершённых функциях
Это MVP, не завершённая production-соцсеть. Ещё не реализованы: подтверждение email и сброс пароля письмом; медиа в личных сообщениях; полноценные ответы на комментарии в интерфейсе; полноценные страницы клана и посты клана; награды/пины профиля; сложный алгоритм рекомендаций; блокировки; полноценное управление ролями через UI; обработка всех жалоб и управление ивентами из UI; облачное постоянное медиа-хранилище (файлы сейчас сохраняются локально на сервере); end-to-end шифрование и push-уведомления.

## Важные замечания по безопасности
- Не публикуй секреты `.env`.
- Перед открытым запуском обязательно настрой HTTPS, резервные копии базы, облачное хранилище медиа, email verification, сброс пароля, CSRF/origin protection и мониторинг.
- Главный администратор создаётся через безопасную первичную настройку `NEXUS_OWNER_*`; не назначай себе роль SQL-командой и не публикуй секреты конфигурации.
- Функции администратора нельзя безопасно включать по кнопке для любого пользователя.

## Публикация
Для публичной работы нужны Node.js hosting и PostgreSQL hosting. Локальная ссылка `localhost` доступна только на этом компьютере; другим людям понадобится опубликованный сервер и HTTPS.


## Фото и видео публикации

Публикации создаются из профиля. Фото попадают в ленту, вертикальные короткие видео (5 секунд–5 минут) — в Shorts, длинные видео (5 минут–24 часа) — во вкладку «Видео». После публикации интерфейс остаётся в профиле. Проверка длительности выполняется в браузере и дополнительно на сервере по переданным метаданным.

Загрузка файлов ограничена 5 ГиБ по умолчанию (`NEXUS_MAX_UPLOAD_BYTES`). Длинные видео требуют большого свободного места на диске и стабильного соединения; для реального публичного сервиса рекомендуется объектное хранилище, потоковая передача и перекодирование видео.

## Серверы и голосовые каналы (NEXUS 2.9)
- Внутри каждого сервера автоматически создаются текстовый канал `общий` и голосовой `голосовой`.
- Участники могут открывать сервер, читать и отправлять сообщения в текстовых каналах, а владелец/модераторы могут создавать дополнительные текстовые и голосовые каналы.
- В каждом голосовом канале есть отдельный чат, доступный участникам этого войса; история чата хранится в PostgreSQL.
- Голос, камера и демонстрация экрана используют WebRTC между участниками через Socket.IO signaling. Для камеры/микрофона/экрана браузер запрашивает разрешения; для production и доступа с других устройств нужен HTTPS. STUN используется для базового соединения; для сетей за строгим NAT/Firewall может понадобиться TURN-сервер.
- Микрофон и камера изначально выключены. Пользователь включает их сам.
